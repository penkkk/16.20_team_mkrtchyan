## 4. Бизнес цель и KPI

**Бизнес-цель:** повысить использование фонда: студенты быстрее находят и открывают нужную IT-литературу.

**KPI:** доля тестовых поисковых запросов, где нужная книга попадает в первые 5 результатов, ≥ 90% (набор T1: 20 запросов по каталогу из ≥100 книг).

## 6. Риски

| Риск | Вероятность | Влияние | Меры предотвращения / реагирования |
|------|-------------|---------|-------------------------------------|
| Несоответствие кейсу 8 | Средняя | Высокое | Зафиксировать бизнес цель, границы проекта с преподавателем. Записать в журнал изменений |
| Авторское право на книги | Средняя | Высокое | Использовать книги с открытой лицензией, собственные учебные материалы, использовать синтетические тексты |
| Перегрузка ролей (один фронтенд, один 1С, три бэкенд) | Средняя | Среднее | Взаимозаменяемость ролей: backend-разработчики при необходимости помогают с реализацией 1С или фронтендом и наоборот, задачи распределяются через RACI |
| Раздувание объёма | Высокая | Высокое | Заморозить MoSCoW к концу второй недели |
| Сложность обработки PDF (извлечение текста, фрагментация, эмбеддинги в pgvector, "битые" и сканированные файлы) | Средняя | Высокое | Реализовывать только как дополнительную функциональность в Could. Для Must более простой вариант поиска |
| Нехватка времени | Высокая | Высокое | Работа по плану выполнения проекта из [Порядок выполнения](./04-execution-procedure.md) |
| Неправильное распределение ответственности между 1С и backend (часть логики реализована не там, где удобнее или эффективнее) | Высокая | Среднее | Заранее определить границу: 1С — справочник и отчётность, backend — основные операции. Решения по границе фиксировать в ТЗ, пересматривать на ревью |
| Реализация может отличаться от документации (например, из-за уточнения требований в процессе разработки) | Средняя | Высокое | Обновлять документы вместе с изменениями (запись в журнале изменений), сверять реализацию с ТЗ перед каждым Gate |
