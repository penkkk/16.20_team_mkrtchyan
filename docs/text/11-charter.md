## 1. Цель и обоснование

**Бизнес-цель:** повысить использование фонда: студенты быстрее находят и открывают нужную IT-литературу.

**KPI:** доля тестовых поисковых запросов, где нужная книга попадает в первые 5 результатов, ≥ 90% (набор T1: 20 запросов по каталогу из ≥100 книг).

**Обоснование.** Начинающему специалисту сложно выбрать нужную книгу среди большого каталога, а в подписочном сервисе ему нужно понимать, почему книга доступна или недоступна ([Анализ рынка](./05-market-analysis.md), раздел 4).

**Отрасль:** образование, электронная библиотека для студентов и IT-специалистов.

## 2. Описание продукта

Для студентов и начинающих IT-специалистов, которым нужно быстро находить профессиональную литературу и получать к ней понятный доступ, ITLib — это учебная электронная библиотека IT-книг по подписке. Она помогает выбирать материалы по технологии, уровню подготовки и учебной цели и прозрачно показывает доступ к чтению.

**Пользователи:**

| Роль | Цель использования |
|---|---|
| Читатель (авторизованный пользователь) | Найти подходящую книгу, проверить доступ и читать её |
| Администратор | Добавлять карточки и файлы книг, контролировать доступность, просматривать аналитику по книгам, пользователям и подпискам |
| Гость | Просматривать каталог и подборки; читать книги без подписки нельзя |

**Отличия от аналогов** (O'Reilly Learning, Habr, Яндекс Книги): русскоязычный контент, доступность из РФ, учебные маршруты по уровням, аналитика для администратора библиотеки. Каталог существенно меньше, чем у O'Reilly, и не включает курсы и видео.

## 3. Границы проекта

Состав требований определяется [MoSCoW](./03-moscow.md).

| Категория | Содержание |
|---|---|
| **Must** | Регистрация и вход по email; каталог с фильтрами по технологии и уровню; обычный поиск по названию и автору; карточка книги; онлайн-чтение для авторизованного читателя; статус подписки как поле в БД; добавление книги администратором; артефакт 1С (справочник «Книги» и отчёт с двумя фильтрами); синтетический набор данных (≥100 книг) и расчёт KPI |
| **Should** | Личная библиотека; топ книг недели; вход через Яндекс и Google; тематические подборки; скачивание книги; оплата подписки через платёжную систему (тестовые платежи); аналитика для администратора (книги, пользователи, подписки) |
| **Could** | Поиск по смыслу (эмбеддинги, pgvector); рекомендации; учебные маршруты по уровням |
| **Won't** | Лицензирование контента и интеграции с издателями; выдачи, возвраты, штрафы и просрочки; мобильное приложение |

## 7. Ограничения и допущения

- Проект учебный.
- Оплата подписки или книги входит в Should (S-6). Интеграция с платёжной системой реальная, платежи тестовые. Пока оплата не реализована, статус подписки задаётся вручную или тестовыми данными.
- Коммерческого контента нет: каталог формируется из книг с открытой лицензией и собственных учебных материалов, так как лицензии издателей не оформлялись.
- Данные синтетические, без персональных данных.
- Финансирование не предусмотрено.
- Обязательно наличие артефакта 1С.

## 12. Открытые вопросы и расхождения в документах

1. **Анализ рынка.** В [описании продукта](./05-market-analysis.md) сказано, что реальные платежи не реализуются, это устарело. В требованиях (раздел 4) заявлен поиск по тексту, а в MoSCoW в Must только обычный поиск по названию и автору.
2. **Аналитика.** Для неё нет use case и записи в [трассируемости требований](./09-requirements-traceability.md).
3. **Правила курса.** Они запрещают боевые интеграции (мок-REST и CSV вместо них). Реальная интеграция с платёжной системой в тестовом режиме боевой не является, но это стоит подтвердить у преподавателя.
