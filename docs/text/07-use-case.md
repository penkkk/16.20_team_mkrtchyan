# Use case электронной библиотеки

## Акторы

| Актор | Тип | Роль и доступ |
|---|---|---|
| Гость | Первичный | Открывает главную, каталог, поиск, рекомендации и карточки книг; регистрируется или входит в систему. |
| Читатель | Первичный | Читает и скачивает книги, ведёт личную библиотеку, покупает подписку. |
| Администратор | Первичный | Добавляет электронные книги через админ-панель. |
| Яндекс ID | Вторичный | Подтверждает вход или регистрацию через Яндекс. |
| Google | Вторичный | Подтверждает вход или регистрацию через Google. |
| Платёжная система | Вторичный | Принимает оплату подписки и сообщает её результат. |

## Подробные сценарии

### UC_1. Регистрация или вход по электронной почте

| Элемент | Описание |
|---|---|
| Предусловие | Гость находится на странице регистрации или входа. |
| Основной поток | 1. Гость выбирает регистрацию или вход по почте.<br>2. Вводит email и пароль.<br>3. Система проверяет корректность данных.<br>4. При регистрации создаёт учётную запись; при входе авторизует пользователя.<br>5. Пользователь перенаправляется в личный профиль. |
| Постусловие | Пользователь авторизован; при регистрации создана новая учётная запись. |

### UC_2. Регистрация или вход через Яндекс / Google

| Элемент | Описание |
|---|---|
| Предусловие | Гость находится на странице регистрации или входа. |
| Основной поток | 1. Гость выбирает «Войти через Яндекс» или «Войти через Google».<br>2. Система перенаправляет его к выбранному провайдеру.<br>3. Гость подтверждает доступ.<br>4. Провайдер передаёт данные пользователя системе.<br>5. Система создаёт или находит учётную запись и авторизует пользователя. |
| Постусловие | Пользователь авторизован в электронной библиотеке. |

### UC_3. Просмотр главной страницы и топа книг недели

| Элемент | Описание |
|---|---|
| Предусловие | Пользователь открыл сайт. |
| Основной поток | 1. Пользователь переходит на главную страницу.<br>2. Система отображает топ книг по количеству просмотров за неделю.<br>3. Пользователь выбирает интересующую книгу. |
| Постусловие | Пользователь может перейти в карточку выбранной книги. |

### UC_4. Поиск книги

| Элемент | Описание |
|---|---|
| Предусловие | Пользователь находится на странице сайта. |
| Основной поток | 1. Пользователь вводит запрос в поисковую строку.<br>2. Система выполняет поиск по названию, автору и смысловому содержанию.<br>3. Система выводит подходящие книги.<br>4. Пользователь открывает карточку выбранной книги. |
| Постусловие | Пользователь получил результаты поиска или сообщение, что книги не найдены. |

### UC_5. Просмотр каталога с фильтрами

| Элемент | Описание |
|---|---|
| Предусловие | Пользователь открыл каталог. |
| Основной поток | 1. Система отображает список книг.<br>2. Пользователь выбирает фильтры, например автора, жанр, год или категорию.<br>3. Система обновляет список книг.<br>4. Пользователь открывает карточку книги. |
| Постусловие | В каталоге отображаются книги, соответствующие выбранным фильтрам. |

### UC_6. Просмотр рекомендаций

| Элемент | Описание |
|---|---|
| Предусловие | Пользователь находится на главной странице, в каталоге или профиле. |
| Основной поток | 1. Система показывает блок рекомендаций.<br>2. Пользователь просматривает предложенные книги.<br>3. Пользователь выбирает книгу. |
| Постусловие | Пользователь переходит к карточке рекомендованной книги. |

### UC_7. Просмотр карточки книги

| Элемент | Описание |
|---|---|
| Предусловие | Пользователь выбрал книгу в топе, поиске, каталоге или рекомендациях. |
| Основной поток | 1. Система открывает карточку книги.<br>2. Отображаются название, автор, описание, обложка, категория и доступные действия.<br>3. Пользователь выбирает «Читать», «Скачать» или возвращается к каталогу. |
| Постусловие | Пользователь получил сведения о книге и может перейти к работе с ней. |

### UC_8. Просмотр личного профиля и библиотеки

| Элемент | Описание |
|---|---|
| Предусловие | Читатель авторизован. |
| Основной поток | 1. Читатель открывает профиль.<br>2. Система отображает данные пользователя, статус подписки и личную библиотеку.<br>3. Читатель выбирает книгу из своей библиотеки. |
| Постусловие | Читатель видит свои сохранённые, открытые или прочитанные книги. |

### UC_9. Чтение книги онлайн

| Элемент | Описание |
|---|---|
| Предусловие | Читатель авторизован; книга опубликована; у читателя есть право доступа к полному тексту. |
| Основной поток | 1. Читатель открывает карточку книги.<br>2. Нажимает «Читать».<br>3. Система проверяет доступ.<br>4. Система открывает встроенную читалку.<br>5. Система фиксирует просмотр книги для статистики. |
| Постусловие | Книга открыта в читалке; просмотр учтён в статистике и, при необходимости, в личной библиотеке. |

### UC_10. Скачивание книги

| Элемент | Описание |
|---|---|
| Предусловие | Читатель авторизован; книга доступна для скачивания; право доступа подтверждено. |
| Основной поток | 1. Читатель открывает карточку книги.<br>2. Нажимает «Скачать».<br>3. Система проверяет доступ.<br>4. Система предоставляет файл книги для загрузки. |
| Постусловие | Файл книги скачан или пользователю показано сообщение об ограничении доступа. |

### UC_11. Покупка подписки

| Элемент | Описание |
|---|---|
| Предусловие | Читатель авторизован и выбрал тариф. |
| Основной поток | 1. Читатель открывает страницу подписки.<br>2. Выбирает тариф.<br>3. Система передаёт данные в платёжную систему.<br>4. Читатель оплачивает подписку.<br>5. Платёжная система сообщает успешный результат.<br>6. Система активирует подписку. |
| Постусловие | У читателя появляется активная подписка и соответствующие права доступа. |

### UC_12. Добавление книги администратором

| Элемент | Описание |
|---|---|
| Предусловие | Администратор авторизован в админ-панели. |
| Основной поток | 1. Администратор открывает форму добавления книги.<br>2. Загружает файл книги и обложку.<br>3. Заполняет название, автора, описание, категорию и параметры доступа.<br>4. Система проверяет обязательные поля.<br>5. Администратор сохраняет книгу.<br>6. Система публикует книгу в каталоге. |
| Постусловие | Новая книга доступна в каталоге и поиске. |

### UC_13. Просмотр статуса подписки

| Элемент | Описание |
|---|---|
| Предусловие | Читатель авторизован. |
| Основной поток | 1. Читатель открывает профиль или страницу подписки.<br>2. Система показывает активный тариф, дату окончания и доступные возможности.<br>3. Читатель при необходимости переходит к покупке или продлению подписки. |
| Постусловие | Читатель знает состояние своей подписки. |

## Содержание use case диаграммы

На диаграмме должна быть граница системы с названием «Электронная библиотека». Внутри границы размещаются use case, снаружи — акторы.

Связи акторов со сценариями:

| Актор | Связанные use case |
|---|---|
| Гость | UC_1–UC_7 |
| Читатель | UC_8–UC_11, UC_13 |
| Администратор | UC_12 |
| Яндекс ID | UC_2 |
| Google | UC_2 |
| Платёжная система | UC_11 |

Связи между use case:

| Основной сценарий | Связь | Включаемый сценарий |
|---|---|---|
| UC_9 «Читать книгу онлайн» | «include» | Проверить доступ к книге |
| UC_10 «Скачать книгу» | «include» | Проверить доступ к книге |
| UC_11 «Купить подписку» | «include» | Оплатить подписку |

На диаграмме не показываются таблицы базы данных, API, сервер, алгоритм смыслового поиска и подсчёт просмотров: это относится к ERD, C4 или технической документации.
