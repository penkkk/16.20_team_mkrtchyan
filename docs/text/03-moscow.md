## 1. Правила приоритизации

- **Must** — без этого нет работающего MVP; критерии приёмки формируются только из этих требований.
- **Should** — важно, но проект можно сдать без этого.
- **Could** — желательно, реализуется при наличии времени.
- **Won't** — сознательно не делается в этой версии.

MoSCoW согласуют Аналитик (BA/SA) + Project Lead с представителем Заказчика. После заморозки изменения вносятся только через change-request (issue с меткой `scope-change`) и фиксируются в [журнале изменений](./10-changelog.md).

## 3. Пояснения

- **Поиск.** Простой поиск (M-3) достаточен для проверки KPI «нужная книга в первых 5 результатах». Поиск по смыслу (C-1) вынесен в Could, так как требует отдельного сервера для модели эмбеддингов и обработки текста книг.
- **Подписка.** В MVP подписка моделируется статусом (M-6), реальная оплата не реализуется (W-1).
