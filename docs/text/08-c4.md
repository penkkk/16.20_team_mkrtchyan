# C4-модель электронной библиотеки

Документ описывает архитектуру электронной библиотеки на двух уровнях C4:

1. **System Context** — место системы среди пользователей и внешних сервисов.
2. **Container** — крупные приложения и хранилища, из которых состоит система.

## Уровень 1. System Context

![System Context Diagram](../schemas/System%20Context%20Diagram.jpg)

Диаграмма показывает электронную библиотеку как единую программную систему. Она позволяет пользователям искать, читать и скачивать книги, добавлять их в избранное, управлять профилем и оплачивать подписку.

### Участники и внешние системы

| Элемент | Тип C4 | Ответственность или связь с системой |
|---|---|---|
| Гость | Person | Ищет и просматривает книги без авторизации. |
| Читатель | Person | Читает книги и управляет своим профилем. |
| Администратор | Person | Модерирует контент и добавляет книги. |
| Электронная библиотека | Software System | Предоставляет функции каталога, чтения, скачивания, профиля и подписки. |
| Yandex ID | External System | Предоставляет OAuth-авторизацию через Яндекс. |
| Google | External System | Предоставляет OAuth-авторизацию через Google. |
| Платёжная система | External System | Обрабатывает и подтверждает оплату подписки. |

### Связи

| Источник | Получатель | Назначение связи |
|---|---|---|
| Гость | Электронная библиотека | Поиск и просмотр книг. |
| Читатель | Электронная библиотека | Чтение книг и управление профилем. |
| Администратор | Электронная библиотека | Добавление и модерация книг. |
| Электронная библиотека | Yandex ID, Google | OAuth-авторизация. |
| Электронная библиотека | Платёжная система | Создание и проверка платежей за подписку. |

## Уровень 2. Container

![Container Diagram](../schemas/Container%20Diagram.jpg)

Контейнерная диаграмма раскрывает внутреннее устройство электронной библиотеки. Каждый контейнер представляет отдельное приложение, сервис или хранилище данных.

### Контейнеры системы

| Контейнер | Технология | Назначение |
|---|---|---|
| UI | React SPA, Nginx | Отдаёт пользователю веб-интерфейс электронной библиотеки. |
| Backend | Go, Gin Gonic | Обрабатывает API-запросы, бизнес-логику, авторизацию, работу с книгами и подписками. |
| Message Broker | RabbitMQ | Передаёт задачи на обработку книг и отправку уведомлений. |
| Search Service | bge-m3, Go | Выполняет семантический поиск и индексирует новые файлы. |
| Database | PostgreSQL | Хранит пользователей, книги, логи авторизации и векторы чанков для поиска. |
| Database | Redis | Кэширует часто используемые запросы и временные данные. |
| Bucket | Garage S3 Bucket | Хранит файлы электронных книг. |

### Основные связи контейнеров

| Источник | Получатель | Взаимодействие |
|---|---|---|
| Пользователь | UI | Работает с веб-интерфейсом через браузер. |
| UI | Backend | Отправляет API-запросы в формате JSON по HTTP. |
| Backend | PostgreSQL | Читает и сохраняет прикладные данные по протоколу PostgreSQL. |
| Backend | Redis | Читает и записывает кэш. |
| Backend | Garage S3 Bucket | Сохраняет и получает книги по S3 API через HTTPS. |
| Backend | Message Broker | Помещает задачи поиска и уведомлений в очередь. |
| Search Service | Message Broker | Получает задачи на индексирование. |
| Search Service | PostgreSQL | Читает и сохраняет векторы поиска. |
| Backend | Search Service | Выполняет запросы семантического поиска по gRPC. |
| Backend | Yandex ID, Google | Выполняет OAuth-авторизацию. |
| Backend | Платёжная система | Создаёт и проверяет платежи за подписку. |

### Легенда

| Обозначение на диаграммах | Значение |
|---|---|
| Зелёный элемент с силуэтом человека | Пользователь или роль пользователя. |
| Синий элемент внутри границы системы | Внутренний контейнер или программная система электронной библиотеки. |
| Оранжевый элемент за границей системы | Внешний сервис, за который команда не отвечает. |
| Цилиндр | База данных. |
| Корзина | Объектное файловое хранилище S3. |
| Пунктирная стрелка | Направленное взаимодействие; подпись описывает действие или протокол. |

## Дальнейшая детализация

При необходимости архитектуру можно развить ещё на двух уровнях C4:

| Уровень | Что будет показано |
|---|---|
| Component | Внутренние модули Backend: авторизация, каталог, поиск, доступ к книгам, профиль, подписки, рекомендации и аналитика. |
| Code | Классы, интерфейсы, контроллеры и репозитории конкретного компонента, например `BookController → BookService → BookRepository`. |
